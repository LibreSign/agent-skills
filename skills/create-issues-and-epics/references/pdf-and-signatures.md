# PDF and signature contracts (conditional)

Load this reference only if the proposed issue affects PDF parsing, writing, rendering, digital signatures, preservation profiles or interoperable document handling. Do not impose PDF-specific checks on other issues.

1. Identify the actual feature, input PDF versions and profiles the product accepts, and output versions and profiles it promises. Check the code, dependency versions, fixtures and existing product documentation. Do not infer that all PDF 1.x, PDF 2.0, PDF/A, PDF/UA or PAdES documents are supported.
2. Consult the applicable **current** primary specifications and their errata, at the relevant clauses: [ISO 32000-2:2020 (PDF 2.0)](https://www.iso.org/standard/75839.html) and its [sponsored copy and errata](https://pdfa.org/resource/iso-32000-2/); [ISO 32000-1:2008 (PDF 1.7)](https://www.iso.org/standard/51502.html) where older files matter; the applicable ISO 19005 part only when PDF/A is promised ([part 4, PDF/A-4](https://www.iso.org/standard/71832.html), is one example, not a blanket requirement); and [ETSI EN 319 142-1](https://www.etsi.org/deliver/etsi_en/319100_319199/31914201/01.02.01_60/en_31914201v010201p.pdf) or [ISO/TS 32002](https://pdfa.org/resource/iso-ts-32002/) only when the relevant signature profile or extension is in scope. Verify the latest applicable revision before citing it. Never claim compliance from a summary alone or invent a clause number.
3. State what existing documents and signatures must preserve. Depending on the change, check earlier PDF versions, incremental updates, pre-existing signatures, field appearances, document permissions, validation behavior and unsupported features. Define realistic fixture tests using representative old and new documents; include a negative case and verify that unchanged paths retain their behavior. An existing signed document must not silently lose validation or be rewritten when the agreed contract forbids it.
4. If a standard or licensed text is unavailable or interpretation remains ambiguous, mark the requirement unresolved and seek a qualified implementer or maintainer decision. Compare other signing tools to discover expectations and useful test cases, then check them against the actual standard and project contract before proposing acceptance criteria.
